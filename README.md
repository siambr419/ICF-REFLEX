# ICF REFLEX

**YOUR ANIME. YOUR UNIVERSE.**

A vanilla HTML / CSS / JavaScript (ES modules) anime discovery and streaming **interface** on Firebase Authentication, Cloud Firestore and Firebase Hosting. No framework, no build step, Spark-plan compatible.

> ICF REFLEX does not host video. It stores metadata and **external HTTPS URLs** (images, embeds, direct files). Nothing is uploaded to Firebase. Only add media you are authorised to distribute or embed.

## Setup (≈15 minutes)

1. **Firebase project** – <https://console.firebase.google.com> → Add project (Spark/free).
2. **Web app** – Project settings → *Your apps* → Web (`</>`). Copy `apiKey`, `authDomain`, `projectId`, `appId` into `public/js/firebase/config.js`. These identify your project; they are *not* secrets and *do not* protect data — the rules do.
3. **Authentication** – Build → Authentication → Sign-in method → enable **Email/Password**. Under *Settings → Authorized domains* add your Hosting domain.
   *Optional:* Templates → Password reset → customise the action URL to `https://YOUR-DOMAIN/reset-password` to use the built-in reset page.
4. **Firestore** – Build → Firestore Database → Create database (production mode, choose a region).
5. **CLI & deploy rules/indexes/site**
   ```bash
   npm install            # dev tooling only
   npx firebase login
   npx firebase use --add # pick your project
   npx firebase deploy --only firestore:rules,firestore:indexes
   npx firebase deploy --only hosting
   ```
   Indexes take a few minutes to build; a query that needs one shows "A required Firestore index is missing" until ready.
6. **Run locally** – `npm run dev` → <http://localhost:5000> (clean URLs, no CSP headers) or `npx firebase emulators:start --only hosting` (real headers incl. CSP).

### Bootstrap the first Super Admin (manual, one time)
Spark has no server for this, so do it in the console:
1. Register a normal account on the site.
2. Firebase Console → Authentication → copy that user's **UID**.
3. Firestore → *Start collection* `userRoles` → Document ID = the UID → fields: `uid` (string, same UID), `role` (string) = `super_admin`, `assignedAt` (timestamp), `assignedBy` (string) = the UID.
4. Log out/in. The **Admin panel** appears in the profile menu. Further roles are assigned in *Admin → Roles* (Super Admin only; rules forbid changing your own role).

### Content workflow
Admin → **Genres** → **Anime** (starts *hidden*) → **Seasons** → **Episodes** → **Video sources** (preview before saving) → set episode *Published* and anime *Public* → **Featured** for homepage rows.

### Media URL guide
* **Images** – any `https://` image URL you are allowed to use (poster 2:3, banner 16:9, thumbnail 16:9). A preview is shown; broken images fall back to a placeholder.
* **Embeds** – paste a normal link; it is converted to the documented embed URL: YouTube (`youtube-nocookie.com/embed/ID`), Vimeo (`player.vimeo.com/video/ID`), Dailymotion, Google Drive `…/file/d/ID/preview`. Anything else is rejected.
* **Direct files** – `https://…/file.mp4|.webm|.ogv|.m4v`. Works only if the host permits hot-linking and the browser supports the codec. Subtitle tracks (`.vtt`) need CORS headers from the host.
* Iframes are created with DOM APIs, host-checked against an allowlist and sandboxed (`allow-scripts allow-same-origin allow-presentation`). Rules re-check embed hosts on write.

## Security model (read this)
* **Enforced by Firestore Rules (server-side):** public sees only `visibility=="public"` anime, published episodes/seasons, active sources; users touch only their own profile fields / watchlist / progress; roles writable only by Super Admin (never self); catalog writes only for content staff with field validation; no client writes to subscriptions/payments; default deny.
* **UX only (client-side):** hidden admin links, role-based menus, `requireRole` screens. They never replace the rules.
* **Content Security Policy** (`firebase.json`) allows scripts only from `self` + `gstatic.com`, frames only from the four embed hosts, no inline script/style. `img-src https:` is broad because admins choose image hosts. If you add social login you must extend CSP and the auth init (popup resolver).
* **Audit logs** are written by the client and are therefore *not tamper-proof*.

## Search, filters, pagination
Firestore has no full-text search. Each anime stores `searchTokens` (word prefixes of the title and alternative titles); search matches **word prefixes** (`nar` → *Naruto*) and is unordered. Browse filters: one filter (genre > year > status > type) runs server-side, the rest narrow each loaded page. Pagination is cursor-based "Load more". 22 composite indexes are in `firestore.indexes.json`.

## Spark-plan limits & known limitations
* Free daily Firestore read/write quotas and 1 GiB storage apply; Hosting has storage/transfer caps. Watch *Console → Usage*. On quota errors the UI shows a message.
* **Trending** is editor-curated (no trustworthy view counter without a server). **Rating** is staff-entered.
* **Watch progress** is tracked precisely for direct video only; embeds only record "opened" (or manual *Mark as watched*) because providers' players need their own APIs.
* Active sources are readable by anyone who knows the (unguessable) episode id even if the episode is unpublished → keep sources *inactive* until publish.
* Deleting anime/seasons/episodes cascades from the browser (no Cloud Functions); an interrupted delete can leave orphans.
* Account suspension, verified audit logs, payments, premium verification, watch party, chat, server-side role provisioning need Cloud Functions/Admin SDK (Blaze plan) — not included.
* UI strings are centralised only partly (`js/i18n.js`: navigation, footer, common); many page strings are still inline English. Other languages, RTL polish, PWA, reviews UI are Phase 2.
* Firebase JS SDK is pinned to **12.0.0** via CDN. Check the latest release and bump with `sh scripts/set-sdk-version.sh <version>`.
* Privacy/Terms are templates, not legal advice. Contact email is unset (`public/js/site.js`).
* `/dashboard/language` is part of *Settings*; `/admin/subtitles` is part of *Video sources*.

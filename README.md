# ICF REFLEX

**YOUR ANIME. YOUR UNIVERSE.**

A vanilla HTML / CSS / JavaScript (ES modules) anime discovery and streaming **interface** on Firebase Authentication, Cloud Firestore and Firebase Hosting. No framework, no build step, Spark-plan compatible.

> ICF REFLEX does not host video. It stores metadata and **external HTTPS URLs** (images, embeds, direct files). Nothing is uploaded to Firebase. Only add media you are authorised to distribute or embed.

## Setup (≈15 minutes)

1. **Firebase project** – <https://console.firebase.google.com> → Add project (Spark/free).
2. **Web app** – Project settings → *Your apps* → Web (`</>`). Copy `apiKey`, `authDomain`, `projectId`, `appId` into `public/js/firebase/config.js`. These identify your project; they are *not* secrets and *do not* protect data — the rules do.
3. **Authentication** – Build → Authentication → Sign-in method → enable **Email/Password**. Under *Settings → Authorized domains* add your Hosting domain.
   *Optional:* Templates → Password reset → customise the action URL to `https://YOUR-DOMAIN/reset-password` to use the built-in reset page.
4. **Firestore** – Build → Firestore Database → Create database (production mode, choose a region).
5. **CLI, choose the Firebase project, deploy rules/indexes/site**
   ```bash
   npm install            # dev tooling only (commit the generated package-lock.json)
   npx firebase login
   npx firebase projects:list          # find your project ID
   npx firebase use --add              # pick it and give it an alias (or edit .firebaserc: {"projects":{"default":"YOUR-PROJECT-ID"}})
   npx firebase use                    # confirm the active project BEFORE deploying
   npx firebase deploy --only firestore:indexes   # composite indexes (fixes "A required Firestore index is missing")
   npx firebase deploy --only firestore:rules
   npx firebase deploy --only hosting
   ```
   Add `--project YOUR-PROJECT-ID` to any command to override the active project. Indexes take a few minutes to build (Console → Firestore → Indexes: all must show *Enabled*); until then queries that need them show the missing-index error. The error message now says what to do and, for admins, links to the Console's index page. `.firebaserc` ships with `icf-reflex` (the project in `config.js`): change it if yours differs.
6. **Run locally** – `npm run dev` → <http://localhost:5000> (clean URLs, no CSP headers) or `npx firebase emulators:start --only hosting` (real headers incl. CSP).

### Bootstrap the first Super Admin (manual, one time)
Spark has no server for this, so do it in the console:
1. Register a normal account on the site.
2. Firebase Console → Authentication → copy that user's **UID**.
3. Firestore → *Start collection* `userRoles` → Document ID = the UID → fields: `uid` (string, same UID), `role` (string) = `super_admin`, `assignedAt` (timestamp), `assignedBy` (string) = the UID.
4. Log out/in. The **Admin panel** appears in the profile menu. Further roles are assigned in *Admin → Roles* (Super Admin only; rules forbid changing your own role).

### Upgrading an existing installation (REQUIRED, once)
Seasons and episodes now carry an `animePublic` flag (used by the security rules so hidden anime cannot leak episodes). Data created before this release does not have it, so **older seasons/episodes stay invisible to visitors until you migrate**:
1. `firebase deploy --only firestore:indexes,firestore:rules` (wait until indexes are *Enabled*).
2. Deploy hosting, log in as an admin, open **Admin → Anime → “Repair visibility flags”** and run it. It only touches documents whose flag is wrong and is safe to repeat. Changing an anime's visibility later re-syncs its seasons/episodes automatically.
3. Existing video sources keep working; review which are *Active* (new ones now start inactive).
4. Email verification is now enforced for watchlist, progress, reports and profile edits. Existing unverified users are sent to `/verify-email` when they open the dashboard.

### Content workflow
Admin → **Genres** → **Anime** (starts *hidden*) → **Seasons** → **Episodes** → **Video sources** (preview, then *Activate*; new sources start inactive) → set episode *Published* and anime *Public* → **Featured** for homepage rows. **Poster Manager** (`/admin/posters`) keeps a library of poster/backdrop/banner/thumbnail image URLs and can apply one to an anime.

### Abyss.to videos
1. Upload the video in your own Abyss.to dashboard (<https://dash.abyss.to/>). Nothing is uploaded to this site, and no Abyss credentials or API keys are used or stored.
2. Copy the video's **Embed URL** (or the iframe snippet; only its `src` is read, never the HTML).
3. Admin → Video sources → choose anime → episode → **New source** → provider *Abyss.to* → paste → name it → *Save*, then **Activate** (and publish the episode / make the anime public).
* **Verification status:** Abyss.to publishes no public embed documentation that could be fetched while building this release. Third-party sources consistently show player URLs of the form `https://abysscdn.com/?v=<VIDEO_ID>`, so that is the one host allowed by default. The dashboard link (`dash.abyss.to`, `abyss.to`) is rejected with an explanation. **If your dashboard's Embed URL uses a different host, nothing is guessed: add the host in all of** `ABYSS_EMBED_HOSTS` (`public/js/utils/url-validator.js`), the `frame-src` of `firebase.json` **and** `vercel.json`, and the `abyss` regex in `firestore.rules` (`embedUrlOk`). `npm test` fails if these drift apart.
* The iframe is sandboxed without popups. If the Abyss player refuses to run inside a sandbox on your account, adjust `EMBED_SANDBOX` consciously; the page shows a hint plus an "open this player in a new tab" link when an embed does not load. Fullscreen is delegated with `allow="fullscreen"`. Playback inside Abyss's player could not be tested here (no network, no Abyss account).

### Poster Manager
`posters` collection: `title, animeId, imageUrl, type (poster|backdrop|banner|thumbnail), altText, isPublished, displayOrder, createdAt, updatedAt, createdBy`. Images are external HTTPS URLs; **Firebase Storage is not configured in this project, so there is no file upload**, and image data is never stored in Firestore. *Apply to anime* copies the URL into the anime's existing `posterUrl` / `coverUrl` (backdrop) / `bannerUrl` field, which every public page already reads, so existing anime images keep working. Deleting a poster record never removes an anime's image. Thumbnails are stored but not applied to an anime field.

### Media URL guide
* **Images** – any `https://` image URL you are allowed to use (poster 2:3, banner 16:9, thumbnail 16:9). A preview is shown; broken images fall back to a placeholder.
* **Embeds** – paste a normal link; it is converted to the documented embed URL: YouTube (`youtube-nocookie.com/embed/ID`), Vimeo (`player.vimeo.com/video/ID`), Dailymotion, Google Drive `…/file/d/ID/preview`. **Abyss.to** URLs are stored exactly as supplied (see below). Anything else is rejected.
* **Direct files** – `https://…/file.mp4|.webm|.ogv|.m4v`. Works only if the host permits hot-linking and the browser supports the codec. Subtitle tracks (`.vtt`) need CORS headers from the host.
* Iframes are created with DOM APIs, host-checked against an allowlist and sandboxed (`allow-scripts allow-same-origin allow-presentation allow-forms`; no popups, no top-navigation). Rules re-check embed hosts on write.

## Security model (read this)
* **Enforced by Firestore Rules (server-side):** public sees only `visibility=="public"` anime; seasons/episodes only when `isPublished` **and** the parent anime is public (`animePublic`, checked against the real anime on every write); sources only when active **and** their episode is published **and** its anime is public (looked up from the episode, so sources of hidden content cannot be listed). Users touch only their own profile / watchlist / progress, and those need a **verified email**. Roles are writable only by a Super Admin (never self). Catalog writes need content staff plus field validation (embed URLs must match the provider's host). No client writes to subscriptions/payments. Default deny. Staff may read/delete watch-progress and watchlist documents **only when the anime they reference no longer exists** (orphan cleanup).
* Rules do not filter: public queries therefore always include the matching `where()` clauses (`isPublished`, `animePublic`, `episodeId`…), otherwise Firestore rejects them. A URL already delivered to a viewer's browser cannot be made secret again; the rules only stop unauthorised access to unpublished/private content.
* **UX only (client-side):** hidden admin links, role-based menus, `requireRole` screens.
* **Content Security Policy** (`firebase.json`, `vercel.json`): scripts only from `self` + `gstatic.com`, frames only from the embed hosts, no inline script/style. `img-src https:` is broad because admins choose image hosts.
* **Audit logs** are written by the client and are therefore *not tamper-proof*.

## Search, filters, pagination
Firestore has no full-text search. Each anime stores `searchTokens` (word prefixes of the title and alternative titles); search matches **word prefixes** (`nar` → *Naruto*) and is unordered. Browse filters: one filter (genre > year > status > type) runs server-side, the rest narrow each loaded page. Search results honour the chosen sort (A–Z, rating, recent) and paginate consistently. Pagination is cursor-based. `firestore.indexes.json` is **generated** from the query list in `scripts/query-manifest.mjs` (`npm run indexes`); a unit test fails if an index is missing, unused, duplicated or if a query changes without the list being updated. Lists that must be complete (seasons, episodes, sources, genres, roles, admin pickers) are read page by page to the end instead of using fixed caps; the admin anime picker is a server-side title-prefix search that loads 25 at a time.

## Sitemap
`npm run sitemap -- https://your-domain.example [project-id]` reads public anime, genres and published episodes of public anime through Firestore's REST API (no credentials) and writes `public/sitemap.xml` (hidden anime, unpublished episodes, admin, dashboard and auth pages are never listed). `--static` lists only the static pages. Add `Sitemap: https://your-domain.example/sitemap.xml` to `public/robots.txt`. Re-run after publishing content.

## Spark-plan limits & known limitations
* Free daily Firestore read/write quotas apply. Loading all episodes of one anime costs one read per episode (paged 100 at a time); very long series cost more.
* **Trending** is editor-curated; **Rating** is staff-entered. Premium, Watch Party, Community, Reviews and Notifications remain *Coming soon* pages.
* **Watch progress** is tracked precisely for direct video only; embeds (including Abyss.to) only record that the episode was opened (`updatedAt` refreshes on every open, position/completed flag are preserved) or a manual *Mark as watched*.
* Deleting anime/seasons/episodes cascades from the browser (no Cloud Functions): it is paged, batched (≤400), stops and reports on the first failing step, and can simply be re-run. Deleting an anime also removes its poster records and, afterwards, users' watch-progress/watchlist references to it (a failure there is reported with a recovery button: Admin → Anime → *Clean orphan references*).
* `animePublic` can be briefly stale if a visibility re-sync fails half-way: use *Repair visibility flags* (an error message tells you when).
* Account suspension, verified audit logs, payments, server-side role provisioning need Cloud Functions/Admin SDK (Blaze plan), not included.
* UI strings are only partly centralised (English only). Firebase JS SDK is pinned to **12.0.0** via CDN (`sh scripts/set-sdk-version.sh <version>`).
* Privacy and Terms are **templates, not legal advice and not legally reviewed**; incomplete parts are highlighted `[OWNER TO COMPLETE]`. The contact email is unset on purpose (`public/js/site.js` → `contactEmail`).
* The home carousel has a pause/resume button, arrow-key navigation, and pauses on hover/focus/hidden tab and with reduced-motion.

## Tests
```bash
npm run test:unit    # URL/Abyss validation, source defaults, search, sitemap, errors, index↔query coverage, CSP/rules/config sync (no Firebase needed)
npm run test:rules   # security-rules suite on the Firestore EMULATOR, project demo-icf-reflex (needs Java + firebase-tools; never touches production)
npm run test:e2e     # real-browser checks (Playwright + Chromium; set PW_REQUIRE_FROM to the node_modules dir holding playwright if it is global): every page at 320/360/375/390/414/768/1024/1280/1440 px for overflow, console errors and missing-index errors, mobile menu, Abyss player, admin Poster/Source flows. Firebase is replaced by tests/e2e/firebase-stub.js
```
The stub is **not** the real Firestore: it checks queries against `firestore.indexes.json` but does not evaluate security rules; run `test:rules` for that. Manual checklist before launch: register → verify → login, a second account trying admin writes (must fail), a hidden anime's episodes not visible to a logged-out browser, an Abyss.to episode on a real phone, keyboard-only navigation, screen-reader pass.
